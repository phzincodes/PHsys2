# Relato privado de vulnerabilidades

Não publique segredos, snapshots, seriais, dados de usuários ou provas exploráveis em Issues públicas. Nenhum repositório remoto ou canal privado de segurança foi configurado ainda.

Durante o desenvolvimento local, comunique o problema diretamente ao responsável pelo workspace em canal privado já estabelecido. Antes de abrir o repositório, o proprietário deve habilitar GitHub Private Vulnerability Reporting e publicar um contato verificado. Não há endereço de email inventado neste documento.

Para escopo e limites dos controles, consulte [docs/SECURITY.md](docs/SECURITY.md).
